The workflow

Three steps to answers

Behind each step is a real pipeline — text extraction, chunking, embeddings, vector search, and an LLM.

STEP 01
📄

Upload

Drop in a PDF or text file. It's extracted, split into overlapping chunks, and each chunk is turned into a vector embedding.

STEP 02
🧠

Understand

Embeddings are stored in a vector index (pgvector). Your question is embedded the same way, so meaning — not just keywords — drives search.

STEP 03
💬

Ask

The most relevant passages are retrieved and sent to the LLM, which answers using only your documents — and cites its sources.

Why it's solid

Built like a product

The details that separate a demo from something you'd actually ship.

🔎

Cited answers

Every answer shows the exact passages it used, with a relevance score — so you can trust and verify it.

🗂️

Multi-document

Ask within one document or across your whole library. Retrieval is scoped per user — nobody sees anyone else's files.

🔌

Swappable models

Flip one env var to move between a local embedder, OpenAI, Groq, or Claude. No code changes.

⚙️

Async processing

Large uploads are embedded on a Celery worker so the UI never blocks. Toggleable for simple deployments.

🧩

Clean REST API

DRF endpoints for uploads, status polling, and chat — with a browsable API and a full Django admin.

🚀

Deploy-ready

Runs on SQLite locally with zero setup; upgrades to Postgres + pgvector for production by config alone.
